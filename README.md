### A few things I've come to believe

**A bug you can't reproduce isn't fixed — it's hidden.** Field-reported issues
need diagnostic logs and a repro path before a fix means anything; that's the
gap between a closed ticket and a customer who stops complaining.

**Field data beats lab data.** A build can pass every regression suite and
still drop calls on a real network with real interference — which is why live
network and operator trials stay part of the sign-off, not a formality after it.

**Localization is a functional requirement, not a checkbox.** One wrong string
in the UI or the Quick Start Guide is a P1 to a market lead, even if every
automated test is green.

**Zero critical errors isn't luck — it's process.** Feature Testing Reports,
structured defect triage, and a build verification pass before every release
are what actually get a device launched clean.
